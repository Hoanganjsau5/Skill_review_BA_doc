# SRC-0005: ISO/IEC/IEEE 12207:2017 (Summary & Verification Note)

- **Source ID:** `SRC-0005`
- **Title:** Systems and software engineering — Software life cycle processes
- **Edition:** First edition (2017-11-01)
- **Authority Level:** `official-standard`
- **Access & Verification Status:** Secondary-source and official catalog verification only. Full ISO/IEC/IEEE copyrighted text is not stored in this workspace. Do not claim verbatim quotations.

## Key Engineering Guidance Extracted
1. **Stakeholder Needs and Requirements Definition (Clause 6.4.2):**
   - Defines stakeholder needs, operational scenarios, and constraints that serve as the authoritative baseline for validating whether software requirements satisfy intended user and business outcomes (`re.requirement-validation`).
2. **System/Software Requirements Definition (Clause 6.4.3):**
   - Requires the software requirement set to be internally consistent, complete across functional/interface/quality/constraint areas within scope, and free from contradictions (`re.requirement-set-quality`).
   - Requires bidirectional traceability between stakeholder requirements, software requirements, architectural/design elements, and verification artifacts (`re.requirement-traceability`).
3. **Validation Process (Clause 6.4.11):**
   - Confirms that the specified and realized software requirements fulfill stakeholder needs and operational use expectations in the target environment.
